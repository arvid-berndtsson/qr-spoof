# Security Policy

## Our Commitment

Security awareness is at the heart of this project. We are committed to maintaining the security of our codebase and ensuring that our educational tools are not misused.

## Purpose

This project exists to **educate users about QR code security risks** (quishing). We believe in:

- Responsible disclosure of security vulnerabilities
- Ethical security research and education
- Transparency in our security practices
- Protecting users from real-world threats

## Reporting a Vulnerability

We take security seriously. If you discover a security vulnerability in this project, please help us protect our users by reporting it responsibly.

### How to Report

**Please DO NOT report security vulnerabilities through public GitHub issues.**

Instead, please report them via:

1. **LinkedIn**: [Arvid Berndtsson](https://linkedin.com/in/arvidberndtsson)
2. **Email**: Contact via LinkedIn for security-related issues

### What to Include

When reporting a vulnerability, please include:

- **Description**: A clear description of the vulnerability
- **Impact**: What could an attacker accomplish with this vulnerability?
- **Steps to Reproduce**: Detailed steps to reproduce the issue
- **Proof of Concept**: If applicable, include a proof of concept (but please don't exploit the vulnerability)
- **Suggested Fix**: If you have ideas on how to fix it, we'd love to hear them
- **Contact Information**: How we can reach you for follow-up questions

### What to Expect

- **Acknowledgment**: We'll acknowledge your report within 48 hours
- **Initial Assessment**: We'll provide an initial assessment within 7 days
- **Updates**: We'll keep you informed of our progress
- **Resolution**: We'll work to resolve the issue as quickly as possible
- **Credit**: With your permission, we'll credit you in our security advisories

### Responsible Disclosure Guidelines

We ask that you:

- Give us reasonable time to fix the issue before public disclosure
- Make a good faith effort to avoid privacy violations, data destruction, and service disruption
- Don't exploit the vulnerability beyond what is necessary to demonstrate it
- Keep the vulnerability information confidential until we've had a chance to fix it

## Security Best Practices for Users

### For End Users

When scanning QR codes:

1. **Always verify the destination URL** before proceeding
2. **Use QR scanner apps with URL preview** features
3. **Be cautious of QR codes** in public places or from unknown sources
4. **Don't enter sensitive information** immediately after scanning a QR code
5. **Check for signs of tampering** on physical QR codes

### For Project Users

When using this project's tools:

1. **Only use for educational purposes** - never create malicious QR codes
2. **Clearly communicate the educational intent** when running awareness campaigns
3. **Obtain proper permissions** before deploying QR codes in any physical location
4. **Follow all applicable laws** in your jurisdiction
5. **Respect privacy** - don't collect or store personal data without consent

## What We Consider Security Issues

### In Scope

- Vulnerabilities that could compromise user data or privacy
- XSS or injection vulnerabilities
- Authentication or authorization bypasses
- Denial of service vulnerabilities
- Security misconfigurations
- Dependency vulnerabilities that could be exploited

### Out of Scope

- Social engineering attacks against project users
- Issues that require physical access to a user's device
- Issues in third-party dependencies (please report directly to the maintainers)
- Issues that require unlikely user interaction
- Theoretical vulnerabilities without practical impact

## Misuse Reporting

If you discover someone misusing this project's tools for malicious purposes:

1. **Do not engage** with the malicious party
2. **Document the evidence** (screenshots, URLs, etc.)
3. **Report to us** via the contact methods above
4. **Report to appropriate authorities** if the misuse involves illegal activity

We will:
- Investigate all reports of misuse
- Take appropriate action, including banning offenders
- Cooperate with law enforcement when necessary

## Security Measures We Take

- **Dependency Scanning**: Regular automated checks for vulnerable dependencies
- **Code Review**: All contributions are reviewed for security issues
- **No Data Collection**: We don't collect or store user data
- **HTTPS Only**: All web traffic is encrypted
- **Regular Updates**: We keep our dependencies up to date
- **Transparency**: We're open about what our code does and doesn't do
